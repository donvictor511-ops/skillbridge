# Database Schema

PostgreSQL, managed with Prisma migrations (`server/prisma/migrations`).
Database names use snake_case. TypeScript names use camelCase.

## users

| Column        | Type      | Rules                                  |
| ------------- | --------- | -------------------------------------- |
| id            | UUID      | Primary key, generated by the database |
| email         | text      | Unique. Stored trimmed and lowercase   |
| password_hash | text      | Argon2id hash. Never the password      |
| created_at    | timestamp | Default: now                           |
| updated_at    | timestamp | Updated automatically                  |

Notes:

- The unique index on `email` also makes login lookups fast.
- Profiles, skills, and portfolio tables are added in Part 4.

## sessions

| Column     | Type      | Rules                                                                  |
| ---------- | --------- | ---------------------------------------------------------------------- |
| id         | UUID      | Primary key                                                            |
| user_id    | UUID      | Foreign key to users.id, ON DELETE CASCADE, indexed                    |
| token_hash | text      | SHA-256 of the session token. Unique. The token itself is never stored |
| created_at | timestamp | Default: now                                                           |
| expires_at | timestamp | 7 days after login                                                     |

Expired rows are ignored when reading. A cleanup job comes later.

## users (new columns)

- `capabilities` account_type[]: what the account can do (`professional`, `client`).
  Strict database enum, because it affects permissions.
- `onboarded_at` timestamp, null until onboarding is finished.

## profiles

One per user (`user_id` unique, cascade delete): `display_name`, `headline`,
`location`, `interests` text[], `goals` text[], timestamps.
Part 4 adds bio, experience, education, portfolio, and visibility.

## skills

Shared catalog: `name` (display text) and `name_key` (lowercase, unique).

## user_skills

Join table. Composite primary key (`user_id`, `skill_id`): the same skill
cannot be added twice. Index on `skill_id`. Cascade delete.
